第 3 章 · 阶段 B LangChain

LangChain：把胶水代码组件化

不用 LangChain

每个项目重写 Prompt / 检索 / 记忆的胶水代码，不可复用、难以维护。

用 LangChain

把组件标准化、可复用、可组合，像搭积木一样拼 LLM 应用。

9 大组件 · 按职责分类
Chat Model
统一 LLM 调用接口
Prompt Template
变量插值复用提示词
Runnable / Chain
统一抽象与流水线
Retriever
检索器接口
Vector Store
向量存储
Memory
跨轮对话状态
Tool
函数 → 工具
Agent
LLM + Tool 决策循环
Output Parser
结构化输出
LCEL 精髓

所有组件都是 Runnable，用 | 串联成流水线 —— 类比 Java Stream.map().filter().collect()

第 3 章 · 代码 examples/02_langchain_demo.py

LCEL 管道符 |

02_langchain_demo.py
LCEL 
 1  from langchain_deepseek import ChatDeepSeek
 2  from langchain_core.prompts import ChatPromptTemplate
 3  from langchain_core.output_parsers import StrOutputParser
 4
 5  prompt = ChatPromptTemplate.from_template("用一句话解释 {concept}。")
 6  model = ChatDeepSeek(model="deepseek-chat")
 7
 8  # ★ LCEL：用 | 把 prompt → model → parser 串成一条链
 9  chain = prompt | model | StrOutputParser()
10
11  # 数据流：{concept} → 填模板 → 发 LLM → 解析成纯字符串
12  result = chain.invoke({"concept": "RAG"})
13  print(result)
| 是什么？

Python 的 | 被 LangChain 重载为 Runnable 串联（运算符重载）。

统一入口

所有组件共享 invoke / ainvoke / batch / stream 四种调用方式。

换模型只改一处

OpenAI / Anthropic / 通义 / DeepSeek 都实现同一抽象。

💡 80% 的"LLM + 提示词 + 检索"场景，默认起点就是 LangChain。

第 4 章 · 阶段 B · 重点 LangGraph

LangGraph：为什么 Chain 不够

Chain 的局限

Chain 是单向流水线；Agent 需要循环 + 条件 + 状态。

LangGraph 的答案

显式状态机 + 图，把 Agent 流程画成可执行的有向图。

💡 一句话：把 Agent 从"黑盒循环"变成"可中断、可观察的流程"。

4 个原语 · Java 类比
Graph
工作流骨架（有向图）
类比 BPMN 流程定义
Node
节点 = 一个函数 (state) → 更新
类比一个 Service 方法
Edge
边 = 跳转（含条件边）
类比状态机的 transition guard
State
节点间共享状态（显式化）
类比流程变量（reducer 控制合并）
人工介入

interrupt_before=["human_review"] —— 在指定节点前暂停，等审批后继续。

第 4 章 · 代码 examples/03_langgraph_demo.py

StateGraph + 条件边 + 人工介入

03_langgraph_demo.py
StateGraph 
 1  from langgraph.graph import StateGraph, START, END
 2
 3  class AgentState(TypedDict):
 4      messages: Annotated[list, operator.add]  # reducer：追加而非覆盖
 5      step: int
 6
 7  graph = StateGraph(AgentState)
 8  graph.add_node("agent", call_model)
 9  graph.add_node("tools", call_tool)
10
11  graph.add_edge(START, "agent")
12  graph.add_conditional_edges("agent", should_continue, {
13      "tools": "tools", "human": "human", "__end__": END,
14  })
15  graph.add_edge("tools", "agent")   # 回环 → 循环
16
17  app = graph.compile(interrupt_before=["human"])
State 显式化

Annotated[list, operator.add] 定义 reducer：消息累加而非覆盖。

条件边

should_continue 返回下一节点名——类比状态机 guard。

tools → agent 回环

工具结果回灌再调 LLM，形成循环——Chain 做不到的。

💡 interrupt_before 让人工审批成为流程的一部分。

RAG 六步管线

04_rag_demo.py
RAG Pipeline 
 1  # Document → Chunk → Embedding → VectorDB → Retriever → LLM
 2  loader = TextLoader("knowledge.txt")
 3  docs = loader.load()
 4
 5  splitter = RecursiveCharacterTextSplitter(
 6      chunk_size=200, chunk_overlap=30)
 7  chunks = splitter.split_documents(docs)
 8
 9  embeddings = SentenceTransformerEmbeddings(
10      model_name="BAAI/bge-small-zh-v1.5")
11  vector_db = Chroma.from_documents(chunks, embeddings)
12
13  retriever = vector_db.as_retriever(search_kwargs={"k": 3})
14  chain = prompt | model | StrOutputParser()
chunk_size 的权衡

太大丢精度、太小断语义；chunk_overlap 保证语义连续。

本地 Embedding

国产 LLM 不提供 Embedding，故用本地 bge-small-zh，无需厂商 Key。

防幻觉

第四问"食堂几点开饭"→ 返回"知识库中未找到"，不编造。

💡 进阶：BM25Retriever + EnsembleRetriever(RRF) 多路召回，再加 Rerank 精排。

第 7 章 · 阶段 C MCP（Model Context Protocol）

MCP：N×M → N+M 的适配地狱

MCP 出现前

每个 Agent 自己接工具，N 个 Agent × M 个系统 = N×M 份适配代码。

用 MCP 后

标准化 "LLM ↔ 工具" 协议，N 个 Agent + M 个系统 = N+M 份实现。

三件套 · 类比 gRPC
Server

暴露工具的服务端（stdio / SSE / WebSocket）

Client

发现并调用工具的客户端（通常是 Agent）

Tool

被暴露的具体能力（docstring 自动转 description）

与 LangChain Tool 的区别

MCP 是跨进程 / 跨语言 / 可复用的标准协议——一个 Server 可被多个 Agent 共享。
