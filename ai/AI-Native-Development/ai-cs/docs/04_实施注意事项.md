## 1. 环境与运行（最高频翻车点）

### 1.1 环境变量清单

| 变量 | 必设 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 是（LLM 环节） | DeepSeek 平台申请；**注意余额**，403/额度类报错先查余额 |
| `DEEPSEEK_BASE_URL` | 可选 | 默认 `https://api.deepseek.com`；换兼容端点才改 |
| `HF_ENDPOINT` | **是** | 必须设 `https://hf-mirror.com`，否则国内下载 embedding/reranker 模型大概率卡死 |
| `TOOLS_MODE` | 可选 | `inprocess`（默认）| `mcp`（M7 用） |
| `RETRIEVER_MODE` | 可选 | `basic` | `hybrid`（M3 用） |

Windows（Git Bash）设置方式：`export DEEPSEEK_API_KEY=sk-xxx`；或写入课程根目录 `.env` 后用 `os.getenv` 读。

### 1.2 venv 与依赖

- **复用课程根 venv**（`AI-Native-Development/.venv`），不要在 ai-cs 下另建——ragas/llama-index 等依赖冲突课程已解决（见根 `requirements.txt` 注释）；
- 激活后在**课程根目录**起服务或跑脚本，或确保 `sys.path` 含课程根（`src/` 内用相对 ai-cs 根的路径计算，见 config.py 设计）；
- **不要装**：opik / guardrails-ai / crewai（与 llama-index 冲突，须独立 venv，本项目用不到）；
- **不要引入 ragas**：其 0.4.x 与 langchain-community ≥0.3 有 import 冲突（根 requirements.txt 已注明需 shim 补丁）。评估用课程 5.4.3 的 keyless 迷你方案。

### 1.3 模型下载（一次性）

```bash
export HF_ENDPOINT=https://hf-mirror.com
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-small-zh-v1.5')"
```

- 缓存于 `~/.cache/huggingface/`，之后纯本地，**不耗 API 额度**；
- reranker（`BAAI/bge-reranker-base`）首次运行自动下载，同样走镜像；
- 卡住/超时 → 先检查 HF_ENDPOINT 是否真的生效（`echo $HF_ENDPOINT`）。

## 2. LangChain API 用法（以课程示例为准，勿凭记忆写）

### 2.1 Agent 组装 ⚠️ 最重要的 API 陷阱

**正确（LangChain 1.x，课程案例用法）**：

```python
from langchain.agents import create_agent
agent = create_agent(model, tools, system_prompt="...")
result = agent.invoke({"messages": [{"role": "user", "content": q}]})
answer = result["messages"][-1].content
```

**错误（旧版已移除，会直接报错）**：

- ❌ `create_tool_calling_agent` + `AgentExecutor`（1.x 已移除，见 `examples/12_case_knowledge_agent.py` 注释）
- ❌ `initialize_agent`（远古 API）

### 2.2 LCEL 链的 dict 陷阱 ⚠️

`RunnableParallel`（链起点的 dict）会把**整个输入 dict** 发给每个分支。Retriever 需要字符串，直接写 `retriever | ...` 会报 `AttributeError: 'dict' object has no attribute 'replace'`。

**正确**：先用 `itemgetter("question")` 抽出字符串再进 retriever（完整写法见 `examples/04_rag_demo.py` 与架构文档 3.2）。

### 2.3 Retriever 的 import 路径

langchain ≥0.3 迁移后（以 `examples/04b_rag_advanced.py` 实际 import 为准）：

```python
from langchain_classic.retrievers import EnsembleRetriever
from langchain_classic.retrievers import ContextualCompressionRetriever
from langchain_classic.retrievers.document_compressors import CrossEncoderReranker
from langchain_community.retrievers import BM25Retriever          # 依赖 rank-bm25
from langchain_community.cross_encoders import HuggingFaceCrossEncoder
```

**写代码前先打开 `examples/04b_rag_advanced.py` 核对当前版本的实际 import**，课程示例是可运行的、与本 venv 版本匹配的唯一可信来源。

### 2.4 Embedding 选型约束

- 用 `langchain_community.embeddings.SentenceTransformerEmbeddings` + `BAAI/bge-small-zh-v1.5`；
- **DeepSeek/通义/智谱不提供 Embedding 接口**——不要尝试用 DeepSeek 做 embedding；
- 建库与查询**必须同一个 embedding 模型**，否则向量空间不一致、检索全错（换模型 = 必须全量重建索引）。

### 2.5 Chroma 持久化

```python
Chroma.from_documents(chunks, embeddings, persist_directory="./chroma_db")
```

- 不指定 persist_directory → 纯内存，重启丢（课程 5.6 明确）；
- 服务进程只读库；重建索引用 scripts/ingest.py **停服或加锁串行执行**，避免并发写坏；
- 换 embedding 模型或改 chunk 参数后，**必须删旧库重建**（维度/内容不一致会导致检索诡异失败）。

## 3. RAG 工程要点（课程 5.8 陷阱清单落地）

### 3.1 切分参数

| 参数 | 取值 | 依据 |
|---|---|---|
| chunk_size | 400（中文） | 课程建议中文 300~800，起步 400 |
| chunk_overlap | 60（15%） | 10%~20% |
| separators | `["\n\n", "\n", "。", "；", " ", ""]` | 中文友好（默认分隔符偏英文） |

**调整纪律**：改参数 → 删库重建 → 跑 `test_rag_offline.py` 看命中率变化，不做无度量的调参。

### 3.2 防幻觉（本项目一票否决项）

三道防线缺一不可：

1. **Prompt 约束**：RAG chain 与 Agent system prompt 都写明"上下文没有就说'知识库中未找到'，禁止编造"；
2. **测试覆盖**：测试集必须含知识库外问题（S4："食堂几点开饭"），断言回答含"未找到"字样；
3. **faithfulness 指标**：评估脚本量化回答被上下文支持的比例，阈值 ≥ 0.8。

### 3.3 检索质量

- 基础版 `k=3` 够 P0；上 hybrid 后**粗召回 k=20 给 rerank 留空间**，`top_n=4` 收口（课程 5.4 配置要点）；
- BM25 路的价值在**精确 token**（工号、单号、专有名词），测试集应包含此类 query 验证 hybrid 增益；
- 别只看 Top1（k=1 易漏）。

### 3.4 知识更新

文档改动 → 重跑 `scripts/ingest.py` 重建索引。**没有重建机制的 RAG 会答旧知识**（陷阱 4）。

## 4. Agent 与工具设计要点

### 4.1 docstring 是 LLM 选工具的唯一依据

课程反复强调：LLM 读工具 docstring 决定何时调用。要求：

- docstring 写清**触发条件**（"当用户问…时调用"），不只写功能；
- 参数说明具体（"员工工号，如 E001"）；
- 工具数量 ≤ 5 个，多了选择准确率下降。

### 4.2 工具返回值规范

- 返回**纯文本字符串**（str），不要返回对象/dict；
- search_policy 的返回**内联来源行**（如 `[来源: knowledge_docs/finance/travel_policy.txt]`），供 LLM 在答案中引用、供 API 层解析 sources；
- 工具内部 try/except，异常时返回友好错误文本（如"工号格式不合法，应为 E+3位数字"），**不要抛异常打断 Agent 循环**。

### 4.3 system prompt 边界声明

明确分工（否则 LLM 乱选）：

- 制度/政策/标准 → search_policy；
- 员工信息（工号/姓名）→ query_employee_db；
- 工单/报销单状态 → query_ticket_status；
- 闲聊/知识库外 → 直接回答或告知未找到，**不调工具**。

### 4.4 稳定性

- `temperature=0.1`（课程案例同款；问答场景要稳定）；
- Agent 每轮 invoke 传全新 messages（本项目无多轮记忆需求，P2 可考虑加会话历史）。

## 5. 测试与评估注意

| 项 | 要求 |
|---|---|
| 离线优先 | `test_rag_offline.py` **不调 LLM 不耗额度**，作为最高频回归（改切分/检索参数后必跑） |
| 场景测试 | `test_scenarios.py` 需 Key 且有随机性 → 断言用关键词包含（gold 关键词 in answer），不做全文相等 |
| 知识库外用例 | 断言含"未找到"，同时断言**未调 search_policy 或调了但答案未被编造**（防双重翻车） |
| 评估指标 | keyless 近似版（课程 5.4.3）：faithfulness/context_precision 用字符集合近似，够用且零依赖 |
| 基线管理 | 首次达标结果存 `tests/baseline.json`；之后每次改动跑对比，回归超阈值要说明原因 |
| LLM 波动 | 指标允许 ±0.1 波动；连续跑 2 次取均值更稳 |

## 6. 常见报错速查

| 报错 | 原因 | 解法 |
|---|---|---|
| `AttributeError: 'dict' object has no attribute 'replace'` | LCEL 把整个 dict 喂给了 retriever | 用 `itemgetter("question")` 先抽字符串（2.2 节） |
| Agent 构造报 `no attribute 'create_tool_calling_agent'` 或类似 | 用了已移除的旧 API | 换 `create_agent`（2.1 节） |
| 403 / Insufficient Balance（DeepSeek） | 账户额度不足 | **本项目历史会话遇到过**：充值或换 Key；离线测试（检索/评估）不受影响 |
| 模型下载卡住 | HF 官网国内不通 | `HF_ENDPOINT=https://hf-mirror.com` |
| 检索结果与语义完全不相关（乱码级错误） | 建库与查询用了不同 embedding，或旧库未删 | 删 chroma_db 全量重建（2.5 节） |
| `No module named 'langchain_classic'` | venv 版本与 import 路径不匹配 | 以 `examples/04b_rag_advanced.py` 实际 import 为准核对 |
| BM25 中文检索无效果 | 未装 rank-bm25 或语料过短 | 确认依赖；语料每节 ≥3 条规则 |
| Windows 路径/编码问题 | 中文路径或默认编码 | 文件读写显式 `encoding="utf-8"`；路径用 `pathlib.Path` |
| Chroma 报 dimension mismatch | 换过 embedding 模型没重建 | 删库重建 |

## 7. 项目纪律与红线

**红线（违反即返工）**：

1. ❌ 不经检索让 LLM 直接回答制度问题（绕过 RAG = 幻觉之源）；
2. ❌ S4 防幻觉用例不通过就继续往下做；
3. ❌ 引入 ragas / opik / crewai 等与现有 venv 冲突的依赖；
4. ❌ 用 DeepSeek 做 Embedding（无此接口）；
5. ❌ Agent 用旧版 AgentExecutor API。

**纪律**：

1. ✅ 每个里程碑完成后跑验收命令、写 `docs/progress.md`；
2. ✅ 改 RAG 参数必删库重建 + 跑离线回归；
3. ✅ 写新模块前先读对应课程示例（映射表见架构文档第 7 节）；
4. ✅ 增量提交 git（每个里程碑至少一次 commit），commit message 含里程碑号。

**风格**：代码含中文注释（与课程一致，便于教学复盘）；关键行标注 Python 语法点（decorator / LCEL 等）；不过度抽象——三个工具就三个函数，不搞工具注册框架。
