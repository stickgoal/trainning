# 01 · 系统分析（ai-cs 企业智能客服系统）

> 状态：规划定稿

## 1. 项目背景与目标

### 1.1 业务背景

某企业内部员工日常大量咨询人事、财务、行政类问题（年假怎么算、报销上限多少、工位怎么申请）。传统方式有三个痛点：

| 痛点 | 现状 | 后果 |
|---|---|---|
| 找不到 | 制度散落在多份文档，员工不知道去哪查 | HR/行政被重复问题淹没 |
| 答不准 | 通用大模型不知道企业私有制度 | 直接问 ChatGPT 会编造答案 |
| 慢 | 问 HR 需要等人工回复 | 简单问题也要等数小时 |

### 1.2 项目目标

构建一个**基于企业内部规章制度的 RAG 智能客服系统**（代号 `ai-cs`，AI Customer Service）：

1. **答得准**：回答必须基于企业制度文档，可追溯到来源（哪个文档哪个章节）；
2. **不编造**：知识库没有的内容，明确回答"未找到"，不允许幻觉；
3. **一个入口两种能力**：既答制度问题（RAG 检索），也查业务数据（MCP 工具，如查员工信息、查工单状态）；
4. **可评估**：有量化指标（检索命中率、回答忠实度），不是"感觉还行"。

### 1.3 非目标（明确不做）

- ❌ 不做微调（Fine-tuning）——课程结论：灌知识用 RAG，不用微调；
- ❌ 不做多轮复杂工作流编排——问答为主，流程简单，按课程选型原则用 LangChain 而非 LangGraph；
- ❌ 不做生产级分布式部署——本项目为课程综合实战，单机可运行即可，但架构预留扩展点；
- ❌ 不做真实企业系统对接——HR/工单系统用模拟数据（内存字典），但接口形态按 MCP 标准设计，可替换。

## 2. 用户角色与使用场景

### 2.1 用户角色

| 角色 | 描述 | 使用方式 |
|---|---|---|
| 普通员工 | 主要用户，咨询制度问题 | Web 页面 / API 提问 |
| HR / 行政管理员 | 维护知识库文档、查看运营统计 | 更新 `knowledge_docs/` 后重建索引 |
| 系统 | 后续实施 Agent / 开发者 | 按开发计划实施、跑测试与评估 |

### 2.2 核心场景（用户故事）

| # | 场景 | 期望行为 | 验证方式 |
|---|---|---|---|
| S1 | "出差住宿每晚最多能报多少？" | 走 RAG：检索制度文档，回答"一线城市 500/晚，二线 350/晚"，并给出处 | 集成测试用例 T1 |
| S2 | "我入职 5 年了有几天年假？" | 走 RAG：按年档规则回答"满 3 年享 10 天"（档位推理） | 用例 T2 |
| S3 | "查一下工号 E001 的员工信息" | 走 MCP 工具：调 `query_employee_db("E001")` 返回部门职位 | 用例 T3 |
| S4 | "公司食堂几点开饭？"（知识库无此内容） | **防幻觉**：明确回答"知识库中未找到"，不编造 | 用例 T4（关键） |
| S5 | "报销单 RB2024001 什么状态？" | 走 MCP 工具：调 `query_ticket_status` 查工单状态 | 用例 T5 |
| S6 | 混合问题："E001 的年假还剩几天？" | Agent 自主决策：先查员工（入职年限）再查制度（年假规则），组合回答 | 用例 T6（进阶） |

### 2.3 典型对话流（目标形态）

```
员工：出差住宿标准是多少？
  ↓ Agent 决策：问制度 → 调 search_policy
  ↓ RAG：多路召回（向量+BM25）→ Rerank → Top3 片段
  ↓ LLM：基于片段生成回答 + 引用来源
系统：按《差旅报销管理制度》第 3 条：一线城市住宿上限 500 元/晚，
      二线城市 350 元/晚。（来源：knowledge_docs/finance/travel_policy.txt）
```

## 3. 功能需求清单

### 3.1 功能分解（FR = Functional Requirement）

#### FR-1 知识库管理
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 加载 `knowledge_docs/` 下多份纯文本制度文档（分域：人事/财务/行政） | P0 |
| FR-1.2 | 文档切分（RecursiveCharacterTextSplitter，中文参数），chunk 携带 metadata（来源文件、域、章节标题） | P0 |
| FR-1.3 | 向量化入 Chroma，持久化到本地目录（重启不丢） | P0 |
| FR-1.4 | 提供重建索引脚本（文档更新后执行） | P1 |

#### FR-2 RAG 检索问答
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 基础 RAG 问答链：检索 Top-K → 注入 Prompt → LLM 生成 | P0 |
| FR-2.2 | 防幻觉约束：Prompt 明确"上下文没有就说未找到" | P0 |
| FR-2.3 | 答案附来源引用（文档名 + 章节） | P1 |
| FR-2.4 | 多路召回：向量检索 + BM25，EnsembleRetriever（RRF 融合） | P1 |
| FR-2.5 | Rerank 精排：bge-reranker-base 交叉编码器，粗召回 k=20 → 精排 top 3~5 | P1 |

#### FR-3 业务数据工具（MCP 形态）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | `query_employee_db(emp_id)`：查员工信息（模拟数据） | P0 |
| FR-3.2 | `query_ticket_status(ticket_id)`：查报销/工单状态（模拟数据） | P1 |
| FR-3.3 | 工具以 MCP Server 形态暴露（FastMCP），Agent 通过 MCP Client 接入；进程内直连作为降级方案 | P1 |

#### FR-4 Agent 编排
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | LangChain `create_agent` 组装：LLM 自主决定调 search_policy 还是业务工具 | P0 |
| FR-4.2 | system prompt 声明工具用途边界（问制度→检索；查工号/工单→调工具） | P0 |
| FR-4.3 | temperature=0.1 低温度，保证问答稳定 | P0 |

#### FR-5 服务接口
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | FastAPI 提供 `POST /api/chat` 接口（入参：question；出参：answer、sources、tool_calls） | P0 |
| FR-5.2 | `POST /api/rebuild` 重建索引（管理用） | P2 |
| FR-5.3 | 极简 Web 聊天页面（单 HTML，调 /api/chat） | P2 |

#### FR-6 评估与质量
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-6.1 | 测试集：≥10 条问答对（含"知识库外"问题） | P0 |
| FR-6.2 | 迷你评估脚本：近似 context_precision / faithfulness（参考课程 5.4.3 keyless 版） | P1 |
| FR-6.3 | 评估报告输出（每次改动后回归对比基线） | P2 |

### 3.2 非功能需求（NFR）

| 编号 | 维度 | 要求 |
|---|---|---|
| NFR-1 | 响应时间 | 单次问答端到端 ≤ 15s（含检索+LLM；本地 embedding 首次加载除外） |
| NFR-2 | 可追溯 | 每条回答能定位到知识来源 chunk |
| NFR-3 | 可观测 | 关键环节（工具选择、检索命中、LLM 调用）打日志 |
| NFR-4 | 环境友好 | 国内可跑通：LLM 走 DeepSeek API，Embedding/Rerank 走本地模型 + HF 镜像 |
| NFR-5 | 成本可控 | 本地 embedding/rerank 不耗 API 费用；LLM 调用低 temperature、上下文只塞精排后片段 |
| NFR-6 | 可替换 | 模拟 DB → 真实系统的替换面收敛在 MCP 工具层，不动 RAG/Agent |

## 4. 技术栈选型（遵循课程综合案例）

**强制约束：使用课程第 13 章案例 1 指定技术栈**（`chapters/13_cases.md` 13.3 节）：

| 层 | 选型 | 依据（课程出处） |
|---|---|---|
| 语言 | Python 3.12 | README 第七节环境要求 |
| LLM | DeepSeek `deepseek-chat`（`langchain-deepseek`） | 课程默认 LLM，OpenAI 兼容，国内可用 |
| Embedding | 本地 `BAAI/bge-small-zh-v1.5`（sentence-transformers） | 第 5 章：国产 LLM 无 Embedding 接口，统一本地 bge |
| 向量库 | Chroma（持久化目录） | 案例指定；轻量嵌入式，百万级以下够用 |
| 切分 | `RecursiveCharacterTextSplitter` | 第 5 章：通用文本首选 |
| 多路召回 | `EnsembleRetriever`（向量 + BM25/`rank-bm25`） | 第 5 章 5.4.1 |
| Rerank | `CrossEncoderReranker` + `BAAI/bge-reranker-base` | 第 5 章 5.4.2 |
| 编排 | LangChain `create_agent`（1.x 入口） | 案例 1 指定；**注意旧 AgentExecutor 已移除** |
| 工具协议 | MCP（`mcp` + FastMCP；进程内 @tool 降级） | 案例 1 指定 |
| Web | FastAPI + uvicorn | 课程 requirements 已含 |
| 评估 | 自写迷你评估（参考 5.4.3） | 避免引入 ragas 的依赖冲突问题 |

**选型决策记录（ADR 摘要）**：

- **ADR-1 为什么不用 LangGraph**：客服问答流程简单（检索→生成），无循环/人工介入，按课程 13.5 选型原则"检索为主、流程简单 → LangChain"。
- **ADR-2 为什么 Embedding 不用 API**：DeepSeek 不提供 Embedding 接口（第 5 章明确），且本地模型不耗额度、数据不出内网。
- **ADR-3 为什么 MCP 工具保留进程内降级**：课程案例 1 就是进程内 `@tool` 模拟（"逻辑等价"）；真实 MCP Server 跨进程会显著增加调试复杂度，P1 阶段再切。
- **ADR-4 为什么评估不用 ragas**：requirements.txt 已注明 ragas 0.4.x 与 langchain-community ≥0.3 存在 import 冲突，需 shim 补丁；课程 5.4.3 提供了 keyless 迷你评估方案，够本项目用。

## 5. 输入与依赖

### 5.1 知识语料（输入）

`knowledge_docs/` 下按域组织纯文本制度文档（UTF-8）：

```
knowledge_docs/
├── hr/
│   ├── leave_policy.txt      # 请假制度（年假/病假/事假/婚产假/审批流）
│   └── employee_handbook.txt # 员工手册（考勤/工位/行为规范）
├── finance/
│   ├── travel_policy.txt     # 差旅报销制度
│   └── expense_policy.txt    # 日常报销制度（餐补/办公用品/审批权限）
└── admin/
    └── it_support.txt        # IT 支持（VPN/账号权限/设备申请）
```

语料要求：结构化分节（`【章节名】` 或 markdown 标题），每节 3~8 条规则，含具体数字（天数/金额/时限），便于出测试题与验证检索精度。**语料内容参考课程 `examples/company_policy.txt` 与 `examples/sample_knowledge.txt` 扩写。**

## 6. 边界条件与关键风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 幻觉（答知识库外问题） | 给员工错误制度信息 → 严重 | Prompt 强约束 + 评估集含"知识库外"用例（S4/T4）|
| chunk 切分不当 | 检索不到正确片段 | 中文 chunk_size 300~500、overlap 10%~20%，按 5.8 节实测调整 |
| Embedding 模型下载失败 | RAG 无法建库 | 强制走 HF 镜像；README 已有预案 |
| DeepSeek 余额不足 | 全系统不可用 | 检索/召回/评估链路设计为可离线验证（不调 LLM）|
| 工具选择混乱（该检索却调工具） | 答非所问 | system prompt 明确边界 + 工具 docstring 精确描述（课程强调 docstring 是 LLM 选工具的依据）|
| Chroma 持久化被并发写坏 | 索引损坏 | 重建索引用脚本串行执行（FR-1.4），服务运行期只读 |

## 7. 验收标准（项目级 DoD）

1. `python scripts/ingest.py` 一键建库成功，输出 chunk 统计；
2. 6 个场景用例（S1~S6）全部按期望行为通过；
3. **S4 防幻觉用例必须通过**（一票否决项）；
4. 评估脚本输出两项指标，测试集 ≥10 条，faithfulness ≥ 0.8；
5. `uvicorn` 起服务后，`POST /api/chat` 可用 curl 验证；
6. 所有回答带来源引用。
