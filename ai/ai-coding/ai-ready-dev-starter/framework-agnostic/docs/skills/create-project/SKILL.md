# 项目脚手架技能（Create Project · 分阶段）

## When To Use

本技能用于在**已拷贝本版文档的空文件夹**中，从零搭建项目骨架。典型场景：用户把 `framework-agnostic/` 目录整体复制到某空目录，然后说"帮我建个项目"，你据此分阶段推进——**一次只执行一个阶段**，逐步把项目建起来。

本版语言/框架无关，故脚手架分三阶段，越往后越具体。

## Rules

### 总原则：三阶段，一次一个

| 阶段 | 名称 | 输入 | 产出 | 是否追问技术细节 |
|------|------|------|------|------------------|
| 1 | `init` | 项目名 + 一句话简介 | 文档骨架初始化（占位符填名称/简介） | 否 |
| 2 | `requirement_clarify` | 与用户对话 | `roadmap.md` + `docs/requirements.md` | 否（只谈需求，不谈栈） |
| 3 | `start_implement` | 技术栈/构建/测试/参考项目等 | 代码骨架 + `docs/tasks/` 任务卡 | 是 |

**逆向禁止**：阶段 2 未产出 `roadmap.md` 与 `docs/requirements.md` 前，不得拆分任务、不得写实现代码。

---

### 阶段 1 · init（仅项目名 + 简介）

1. **读文档**：`AGENTS.md` → `README.md` → `docs/*.md`，理解文档结构与占位符。
2. **只问两项**：
   - Q1：项目名（英文，用作目录名与文档标题）
   - Q2：一句话简介（业务/用途描述）
3. **初始化文档骨架**：把 `AGENTS.md` / `README.md` / `docs/*.md` / `CHANGELOG.md` 中的 `<!-- 项目名 -->`、`<!-- 简介 -->` 等占位符填为实际值；语言/框架相关占位**保持占位**，留待阶段 3。
4. **不动代码**：本阶段不创建源码目录、不装依赖、不写实现。
5. **告知下一步**：输出「项目已初始化：`<项目名>` —— <简介>。下一步进入需求澄清（requirement_clarify）。」

---

### 阶段 2 · requirement_clarify（与用户讨论需求，产出 roadmap + 需求文档）

1. **读阶段 1 成果**：确认 `AGENTS.md` 中项目名/简介已就位。
2. **与用户对话澄清需求**，覆盖：核心用户与场景、关键功能清单、非功能诉求（性能/安全/合规）、范围边界（明确不做什么）、成功标准。
3. **产出两份文档**：
   - `roadmap.md`（项目根目录）：顶层开发路线图。按里程碑/阶段划分，每阶段含目标、范围、大致顺序、可交付物。不与具体技术栈绑定。
   - `docs/requirements.md`：需求文档。功能需求（编号 FR-xx + 描述 + 验收要点）、非功能需求（NFR）、范围边界、术语表。
4. **不写代码、不拆分任务**：本阶段只定"做什么"，不定"怎么做"。
5. **门禁**：两份文档均经用户确认后，方可进入阶段 3。

> roadmap.md 模板要点：
> ```
> # <项目名> 开发路线图
> ## 里程碑概览
> | 阶段 | 目标 | 范围 | 交付物 |
> | M1 | ... | ... | ... |
> ## 各阶段说明
> ### M1 ...
> ```

---

### 阶段 3 · start_implement（索取技术细节，搭骨架，拆任务）

1. **依据 `roadmap.md` + `docs/requirements.md` 拆分任务**：在 `docs/tasks/` 下按里程碑逐个写任务卡（`TEMPLATE.md`），每张卡含可验证验收标准，映射到 `roadmap.md` 的阶段。
2. **向用户索取技术相关信息**（按本版特性）：
   - Q1：后端语言与框架（如 Java/Spring Boot、Go/...）
   - Q2：前端框架（如 Vue/React/无）
   - Q3：构建工具与包管理（Maven/npm/...）
   - Q4：测试框架
   - Q5：包根 / 目录命名约定
   - Q6：是否需要中间件/数据库（列表）
   - Q7：是否有参考项目可借鉴（路径）
3. **搭最小可运行骨架**：按用户选定栈生成目录、依赖描述、最小入口与一条冒烟接口（不含需求外功能）。
4. **收尾**：在 `CHANGELOG.md` 追加 `init: 初始化 <项目名> 骨架（阶段 M1）`；过程中发现的坑回写 `docs/skills/` 对应 Common Mistakes。

## Examples

```
用户：把 framework-agnostic 拷到 D:/proj/notes，建个项目。
AI[阶段1 init]：项目名？简介？ → notes / 个人笔记与知识管理
  → 文档占位填名称/简介，无源码。
AI[阶段2 requirement_clarify]：聊需求 → 产出 roadmap.md + docs/requirements.md（M1 笔记 CRUD / M2 搜索 / M3 标签）
  → 用户确认。
AI[阶段3 start_implement]：后端栈？前端？构建？→ Go+Gin / 无 / go mod / testify
  → 生成 Go 骨架 + tasks/TASK-001-笔记CRUD.md，CHANGELOG 追加 init。
```

## Common Mistakes

- **阶段 1 就问技术栈**：init 只收集名称+简介；栈留到阶段 3。
- **跳过需求澄清直接实现**：未产出 `roadmap.md` + `docs/requirements.md` 就写代码，违反 7.6。
- **roadmap 绑定技术栈**：路线图谈"做什么/顺序"，不谈"用什么框架"。
- **占位符残留**：阶段 1 至少清零名称/简介类占位；阶段 3 清零全部。
- **一次执行多阶段**：严格一次一个阶段，阶段间经用户确认再继续。
