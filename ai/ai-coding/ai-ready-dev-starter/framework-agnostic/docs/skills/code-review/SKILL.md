# Code Review 技能（语言无关）

## When To Use

提交前自查、评审他人代码时。Review 是质量保障的最后一道关。

## Rules（检查清单）

### 分层与结构
- [ ] 路由/Controller 是薄层，无业务逻辑
- [ ] 业务逻辑在业务层
- [ ] 没有反向或跨层调用
- [ ] DTO 与实体分离，不泄露内部字段

### 返回与异常
- [ ] 所有 API 返回统一响应结构
- [ ] 业务校验抛业务异常，无裸异常、无吞异常
- [ ] 错误码集中，无散落字符串

### 事务与并发
- [ ] 跨多表写操作在一个本地事务内
- [ ] 扣减类操作用条件更新防超卖，无"先查后改"

### 数据库
- [ ] 字符集/编码统一
- [ ] 状态字段走枚举，无魔法数字
- [ ] 复杂查询与简单 CRUD 分离
- [ ] 业务数据软删除，无物理删

### API 契约
- [ ] 路径前缀统一，资源复数名词
- [ ] HTTP 动词语义正确
- [ ] 创建类接口考虑幂等

### 架构边界
- [ ] 未引入 `AGENTS.md` 禁止的中间件
- [ ] 新依赖/中间件引入前已补 ADR

### 基础项
- [ ] 命名清晰，无魔法数字
- [ ] 无空指针风险
- [ ] 日志合理（关键路径有日志，不刷屏）
- [ ] 无调试残留（print、注释掉的代码）

## Common Mistakes

- **只看功能不看分层**：功能对但路由层塞业务，埋技术债。分层是硬约束。
- **放过并发隐患**：`if (stock >= qty) update` 看着对，并发下却超卖。
- **忽略事务边界**：跨表写没在一个事务内。
- **漏看字符集**：新增表/字段没指定编码。
- **不查禁止清单**：顺手引入禁止的中间件。
- **放过调试残留**：print、注释代码块混在提交里。
