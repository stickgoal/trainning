# 测试技能（语言无关）

## When To Use

为代码写测试、补测试、排查测试失败、评估覆盖率时。

## Rules

- **单元测试为必须项**：新增/修改业务方法必须配套单元测试，不允许只写实现不写测试。
- **单元测试 mock 数据层**：mock 掉数据层与外部依赖，不连数据库、不连网络，跑得快、可重复。
- **集成测试走完整链路**：真实走接口 → 业务 → 数据 → 数据库，验证链路。
- **写数据测试加事务回滚**：测试结束自动回滚，防跨测试数据污染。
- **覆盖率门槛**：核心业务（事务、状态机、计算）行覆盖率 ≥ 80%，新增代码不低于既有基线。
- **覆盖优先级**：事务一致性 > 边界与异常 > 正常路径。
- **命名**：`方法名_场景_预期`，如 `createOrder_库存不足_抛异常`。
- **断言具体值**：断言到具体字段值，不用 `assertNotNull` 凑数；异常断言到具体类型与错误码。
- **验证 mock 调用**：`verify(mapper, times(1)).deduct(...)` 验证调用次数与参数。
- **测试独立**：测试间不共享状态、不依赖执行顺序，自带数据构造（given/when/then）。

```
# given/when/then 三段式
# given  构造输入与 mock 行为
# when   调用被测方法
# then   断言结果 + 验证 mock 调用
```

## Common Mistakes

- **缺事务回滚导致数据污染**：测试间互相影响，偶发失败难定位。
- **只测正常路径**：覆盖率高但边界（空、超量、非法状态）全漏。
- **模糊断言**：`assertNotNull(result)` 凑数。断言到具体值。
- **测试依赖顺序**：A 测试设的数据 B 测试用，A 改 B 挂。测试应独立。
- **跳过失败测试**：掩盖问题。先修再说，不留烂尾。
- **依赖外部服务**：测试连第三方 API，环境一变就挂。用本地或 mock。
- **不写单元测试直接上集成测试**：集成测试慢、难定位，先用单元测试锁住逻辑分支。
- **覆盖率造假**：删断言、写空测试凑覆盖率。覆盖率是手段不是目的。
