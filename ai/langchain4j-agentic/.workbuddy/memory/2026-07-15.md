### langchain4j agentic API 关键事实（1.16.0-beta26，源码在 .scratch/lc4j_src 或 D:/appData/mvnrepo ...-sources.jar）
- PendingResponse：构造 `new PendingResponse<>(responseId)`；`blockingGet()`(=future.join)、`complete(value)`、`responseId()`、`isDone()`；Jackson `@JsonCreator` 仅序列化 responseId。
- AgenticScope：`state()` 返回原始 Map(含 PendingResponse 对象，不阻塞)；`readState(key)` 对 DelayedResponse 会阻塞；`pendingResponseIds()` 返回未完成 responseId 集合；`completePendingResponse(responseId,value)`；实现 `AgenticScopeAccess` 的 workflow 代理可 `getAgenticScope(memoryId)`/`evictAgenticScope(memoryId)`。
- `@V`=dev.langchain4j.service.V，`@MemoryId`=dev.langchain4j.service.MemoryId，`@Agent`/`@HumanInTheLoop`=dev.langchain4j.agentic.*。
- 工作流方法：`String process(@MemoryId String id, @V("k") String v, ...)`；memoryId 即 scope key。

## awaitPause 忙等优化为事件驱动（提交 744968c）
原 `awaitPause` 用 `while + Thread.sleep(100)` 轮询 `pendingResponseIds`，把 HTTP 线程挂在 precheck LLM 整段时间且空转。优化：
- `ApprovalService` 注册 `AgentListener`（`inheritedBySubagents()=true`，会经 `registerInheritedParentListener` 透传到子 agent）：`afterAgentInvocation` 中若 `resp.output() instanceof PendingResponse` 即暂停点到达，把 `resp.agenticScope()` 投递给 `pauseSignals.get(businessId)`。
- `submitRefund`/`recover` 改用 `pauseSignal.get(PAUSE_TIMEOUT_MS, MS)`（OS 级阻塞，零 CPU）替代轮询；工作流在暂停点前失败时 `pauseSignal.completeExceptionally(t)` 主动解除等待。
- 新增 `pauseSignals` map、`onApprovalPaused`、常量 `APPROVAL_PREFIX`；删除 `awaitPause`/`sleep`。
- 编译 BUILD SUCCESS(66 文件)。教程 Step2(加listener)/Step3(事件驱动+为何不用轮询的callout)/Step4/Step6/gantt/11.6/11.8 同步。
- API 事实：AgentResponse record 提供 `agenticScope()`/`agent()`/`output()`/`inputs()`；listener `inheritedBySubagents=true` 才会透传到 sequence 的子 agent。
