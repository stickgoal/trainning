## Planner 模式案例实现

- 新增第 7 种 Agentic 工作流模式：**Planner（规划-执行）**
- 实现 Planner 核心：Plan-then-Execute 两阶段范式
- 业务场景：批量售后工单智能规划

### 创建的文件

1. `planner/PlannerWorkflow.java` — 工作流顶层接口
2. `planner/agent/PlanAgent.java` — 规划 Agent：分析批量工单生成 JSON 执行计划
3. `planner/agent/PlannerExecuteAgent.java` — 执行 Agent：按计划逐步处理工单
4. `planner/agent/ProgressAgent.java` — 进度 Agent：检查计划完成度
5. `planner/service/PlannerService.java` — 组装 Sequence(PlanAgent → Loop(ExecuteAgent, ProgressAgent))
6. `planner/controller/PlannerController.java` — REST 入口 POST /api/planner/plan

### 关键技术点

- **架构**: `Sequence(PlanAgent → Loop(PlannerExecuteAgent ↔ ProgressAgent))`
- **退出条件**: ProgressAgent 输出含 "ALL_COMPLETED"
- **上下文传递**: `summarizedContext` 自动在 Loop 迭代间传递执行结果
- **与 Supervisor 区别**: Planner 是"先规划后执行"（白盒），Supervisor 是"运行时动态决策"（黑盒）

### 问题修复

- **Bean 名称冲突**: `planner.agent.ExecuteAgent` 与 `humanintheloop.agent.ExecuteAgent` 同名，改名为 `PlannerExecuteAgent`
- **Dashboard 更新**: index.html 新增第 7 种模式卡片、架构图、API 表
- **模板变量缺失 (progressResult)**: `PlannerExecuteAgent` 的 `@UserMessage` 引用了 `{{progressResult}}`，但 Loop 第一轮迭代时该变量不存在。修复：移除模板中的 `{{progressResult}}`，仅靠 `summarizedContext = {"progressResult"}` 自动注入（与现有 DraftAgent 模式一致）。同时移除 ProgressAgent 上冗余的 `summarizedContext`。
- **关键模式**: Loop 中 `summarizedContext` 负责上下文注入，不要在 `@UserMessage` 模板中用 `{{}}` 引用同一个变量；`@V` + `{{}}` 仅用于上游 agent `outputKey` 设定的值。
- **计划状态不累积 (第二次修复)**: 原实现 PlannerExecuteAgent 每轮读 `@V("batchPlan")` 原始计划，导致永远只处理第一个工单、进度卡在 1/3。修复：改用**单一可变 `plan` 状态**——PlanAgent 与 PlannerExecuteAgent 共用 `outputKey="plan"`，ExecuteAgent 每轮读 `@V("plan")` 并覆写为更新后的计划（已处理步骤标记 COMPLETED），ProgressAgent 读 `@V("plan")` 检查进度。下一轮 `@V("plan")` 自动解析到累积更新后的计划。
