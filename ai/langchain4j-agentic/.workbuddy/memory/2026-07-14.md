## HumanInTheLoop 生产级改造（包 com.example.agentic.humanintheloop）
将原本 Demo 化的人工介入流程改造成生产级：
- 两个硬性约束：① 状态落库不用内存 Map；② 不用线程池 Future 阻塞等待。
- 核心改动：新增 `approval_request` 表（状态机 PENDING_PRECHECK→AWAITING_APPROVAL→EXECUTING→EXECUTED/REJECTED，异常 FAILED）；审批改为「条件更新 + 异步执行 + 202 立即返回」；结果用 `GET /status` 轮询。
- 新增文件：entity/ApprovalRequestEntity、mapper/ApprovalRequestMapper、model/ApprovalStatus、model/ApprovalResponse、config/HumanInTheLoopConfig（ThreadPoolTaskExecutor + @EnableAsync/@EnableScheduling，卡滞恢复默认关闭由 humanintheloop.recovery.enabled 控制）。
- 重写：service/HumanInTheLoopService、controller/HumanInTheLoopController（新增 GET /status，approve 返回 202）。删除：HumanApprovalWorkflow.java（不再用库内阻塞 PendingResponse）。
- AgenticDemoApplication 的 @MapperScan 范围放宽到 com.example.agentic。
- docs/init.sql 追加 approval_request 建表；docs/humanintheloop-refactor-proposal.md 为改造建议文档。

## 环境备注（编译）
本机 maven 在 Git Bash 下 `mvn`/`mvn.cmd` 均异常（cmd //c 吞命令、mvn 脚本 classpath 解析失败）。
可用直接调 java 启动 maven launcher 编译：
```
JAVA_HOME="D:\apps\jdk-17.0.16"
CP="D:\apps\apache-maven-3.9.11\boot\plexus-classworlds-2.9.0.jar"
MH="D:\apps\apache-maven-3.9.11"
PROJ="D:\workspace\处理\trainning\ai\langchain4j-agentic"
java -classpath "$CP" -Dmaven.home="$MH" "-Dclassworlds.conf=$MH\bin\m2.conf" "-Dmaven.multiModuleProjectDirectory=$PROJ" org.codehaus.plexus.classworlds.launcher.Launcher -o clean compile
```
路径必须用 Windows 反斜杠，否则 java 找不到 classworlds jar。本次已验证 BUILD SUCCESS（63 文件编译通过）。
