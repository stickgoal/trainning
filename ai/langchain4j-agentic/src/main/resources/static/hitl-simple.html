HumanInTheLoop 极简教学版

挂起/恢复机制最简单直观，但「审批前分析」和「审批后执行」由真实 LLM Agent（LangChain4j AiServices）完成，不是模拟。 ← 返回主看板

🧠 核心原理（记住三样东西）

HITL 把一条流程切成两段，用「挂起状态 + 关联令牌」接起来，因为 HTTP 不能在等人工时一直占着线程：
① 提交AI Agent 跑「审批前」分析 → 冻结状态，返回 requestId
→
② 人工在别处看到 requestId，做出审批决策
→
③ 恢复AI Agent 按人决策跑「审批后」执行，返回结果
  • 挂起状态：暂停时保存的上下文（本例用内存 Map 存 PendingRequest）。
  • 关联令牌：requestId，连接「提交」和「审批」两条 HTTP 请求。
  • 人工决策通道：独立的 /approve 接口，专门接收人的输入。

对比官方版：LangChain4j 的 @HumanInTheLoop 用 PendingResponse+AgenticScope 隐式做同样的事， 并用线程阻塞在一个调用里串起挂起-恢复；这里拆成两条请求，更直观，也更适合 Web 场景。
